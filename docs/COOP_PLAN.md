# План: Кооперативный мультиплеер 2–4 (v0.5 → v1.0)

Статус: ПЛАН (реализация не начата). Архитектура: хост-авторитарный P2P через WebRTC (PeerJS).

---

## 0. Ключевые архитектурные решения

| Решение | Выбор | Почему |
|---|---|---|
| Кто держит состояние | **Только хост** | Движок — рефери уже сейчас; «ИИ предлагает — код решает» сохраняется. Клиенты — тонкие терминалы |
| Транспорт | **WebRTC DataChannel, signaling через PeerJS** | Без своего сервера. Публичный брокер `0.peerjs.com` бесплатен |
| Модель синхронизации | **Пошаговая, round-robin** | Ходы по очереди: `@ → # → Ω → монстры`. Убирает все гонки заодно |
| Чьё API-ключ | **Хоста** | Клиентам ключ не нужен. ИИ видит всю партию |
| Комната | **Короткий код = peer-id хоста** | Хост жмёт «Создать комнату» → код `XXXX`; друзья вводят код |

## 1. Протокол (DataChannel, JSON)

```
клиент → хост:  {t:'hello', name, ver, heroIdx}   # рукопожатие; heroIdx — заявка «я вернулся»
хост → клиент:  {t:'welcome', playerId, name, heroIdx, resumed}  # name — ВЫДАННОЕ имя (тёзка → суффикс)
хост → клиент:  {t:'lobby', players[], started}   # лобби; offline:true — игрок ждёт переподключения
клиент → хост:  {t:'intent', command}             # свободный текст, как в соло
хост → клиент:  {t:'events', seq, events[]}       # события хроники (упорядочены!)
хост → клиент:  {t:'snapshot', seq, map, you, heroes[], turnOf, merchant}  # раз в ход
хост → клиент:  {t:'start', worldDesc, mode, resumed}  # старт партии (в т.ч. после перезапуска хоста)
хост → клиент:  {t:'ping'/'pong'}                 # keepalive
хост → клиент:  {t:'kick', reason}
```

Правила:
- `seq` — монотонный номер пакета; клиент буферизует и рисует по порядку (боремся с перепутанным порядком сообщений).
- `snapshot` — **персональный**: хост вырезает из карты только клетки FOV конкретного игрока и видимых им монстров/предметов. Скрытая информация по сети не течёт.
- Рукопожатие несёт `ver` протокола; несовпадение → отказ с сообщением.
- **Возврат после обрыва**: хост не убивает героя сразу, а держит его в `absent` (`RECONNECT_GRACE_MS`, 3 минуты). Клиент повторяет `hello` с именем, **выданным хостом** (не набранным в поле — иначе тёзка уведёт чужой слот), и получает `welcome{resumed}` + `start` + свой `snapshot` с тем же `heroIdx`.
- **Перезапуск хоста**: состояние пишется в localStorage после каждого хода (`meta.coop`, `meta.room`). «Продолжить» поднимает комнату с тем же кодом, герои 1..n попадают в `absent` и возвращаются сами.

## 2. Изменения в движке (M0)

Сейчас `state.pos` — один герой. Нужно:

- `state.heroes: Hero[]` — каждый со своими pos, hp, inventory, fov; `state.activeHeroIdx`
- Все функции `applyIntent` принимают `heroIdx`; монстры целятся в ближайшего **видимого** героя
- Инициатива раунда: герои ходят строго по очереди, монстры — после всех героев
- FOV рендерится как объединение (хост) или персонально (клиент)
- Партия мертва, когда мертвы все (общий экран смерти); погибший герой → наблюдатель
- Лут и лестница: «спуск» доступен, только когда все живые герои на лестнице (иначе один качает левелы, остальные теряются)

## 3. Транспортный слой (M1)

Абстракция `Transport` (send/onMessage/onClose), две реализации:
- **LoopbackTransport** — всё в одном процессе: хост-клиент, хот-сит и интеграционные тесты
- **PeerTransport** — обёртка над PeerJS

Код UI не знает, какой транспорт активен. Это же позволит тестировать мультиплеер в node:test без браузера.

## 5. ⚠️ Уязвимые места и мины (главное!)

### Сетевые
1. **PeerJS-брокер ляжет → мультиплеер мёртв.** Митигирование: ручной режим без signaling (обмен SDP-жгутами копипастой) как fallback; код транспорта уже абстрагирован.
2. **Symmetric NAT / корпоративные сети** — P2P без TURN-сервера не пробьётся (~10–15% случаев). TURN свой = сервер и деньги. Решение v1: честное сообщение «не удалось соединиться, попробуйте другую сеть». Решение v2 (опционально): бесплатный TURN от Cloudflare/OpenRelay.
3. **Хост закрыл вкладку = мир умер.** Миграция хоста — это передача сериализованного state + переподключение каналов. Сложно и хрупко. **Вне скоупа v1** — просто «Хост потерян, создайте комнату заново».
4. **Порядок сообщений DataChannel не гарантирован** между разными каналами; внутри одного — упорядочен (reliable mode). Всё в один канал + `seq` — и не паримся.

### Игровые
5. **AFK-игрок блокирует очередь ходов.** Таймер хода (60 сек, настраиваемо) → авто-«постоять». Плюс команда «передаю ход».
6. **Ливнущий игрок.** Его герой: пауза-статуя до возвращения (reconnect по тому же peer-id сложен) → проще: host может выгнать (kick), герой рассыпается на лут. Жестоко — в стиле игры.
7. **Снежный ком ИИ-затрат.** Свободный текст каждого игрока = вызов API на ключе хоста. Лимит: cooldown 10 сек на свободное действие на игрока + баннер «ключ оплачивает Дима».
8. **Читинг клиента.** Клиент — тонкий, все интенты проходят движок хоста, максимум «спам мусором». Но снапшот можно декодировать из памяти вкладки — перс. FOV уже решает 90%. Для друзей-коопа приемлемо.
9. **Спуск вперёд всех.** Решено правилом «все на лестнице» (см. §2).
10. **Дедлок лута** — два героя на одной клетке: лут уходит первому, кто «поднимаю» в СВОЙ ход. Очередь ходов решает.

### UI/UX
11. **Два `@` на карте** — каждому игроку свой яркий символ + подсветка «ты здесь»; чужих героев видно только в общем FOV.
12. **Кто сейчас ходит?** — постоянный индикатор «Ход: Дима (30с)» — иначе вечное «а чей ход?».
13. **Печатная машинка на 4 игроков** — очередь событий может копиться быстрее печати. Скорость печати автопонижается при очереди > 3 строк; клик по хронике уже проматывает.
14. **Кириллица в именах игроков** — экранировать всё через esc() везде (XSS через имя — реальная дыра в innerHTML-рендере, у нас уже есть esc, не забыть в лобби).

### Инфраструктурные
15. **Версии клиента и хоста разъехались** — после апдейта друзья со старой вкладкой: `ver` в handshake, понятная ошибка «обнови страницу».
16. **Тестирование P2P** — нельзя автотестом в CI поднять два браузера. Поэтому: вся логика поверх LoopbackTransport покрывается тестами; PeerTransport — тонкий (должен быть < 100 строк) и проверяется руками двумя окнами. Чек-лист ручного плейтеста приложить в PR.
17. **GitHub Pages** — статика, работает; но PeerJS-брокер по HTTPS ок, а `location.protocol` проверять (http-версия локально сломает secure WebRTC).

## 6. Тесты (обязательные до мержа каждой вехи)

- M0: очередь ходов, смерть партии, правило «все на лестнице», фокус монстров на видимых героях, персональный FOV
- M1: интеграционный тест — 2 Loopback-клиента + хост: полный цикл hello→welcome→intent→events→snapshot; ливень из 500 команд без рассинхрона seq
- M1: тест «клиент шлёт мусор/подделку» — движок не должен падать (уже есть паттерн applyDmEffects)
- M3: таймаут соединения, повторный join с тем же именем, kick

## 7. Definition of Done

Два человека в разных сетях (не LAN) играют в один подземелье 15+ минут: ходят по очереди, дерутся общими силами, ИИ издевается над обоими, кто-то умирает и наблюдает, партия доходит минимум до 3-го этажа. Всё это — по ссылке с GitHub Pages.
