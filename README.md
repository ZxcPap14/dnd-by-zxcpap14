# dnd by ZxcPap14

ASCII-рогалик в стиле D&D с полностью ИИ-управляемым миром.

Янтарный ретро-терминал, туман войны, честные d20, permadeath, ДМ-тролль.

## Особенности

- **Только свободный текст** — никаких кнопок: «иду на север», «пробую подкупить стражу»
- **ИИ предлагает — код решает**: ИИ-мастер ведёт историю, но кубики кидает честный RNG движка
- **Сеттинг задаёшь ты** — «пиратский корабль, проклятый кракеном» или что угодно
- **Способности придумывает игрок** — ИИ интерпретирует, движок считает
- **Забег переживает закрытую вкладку** — автосейв после каждого хода, на старте появляется «ПРОДОЛЖИТЬ». В коопе хост возвращается в ту же комнату с тем же кодом
- **Торговец между этажами** — тратить золото: зелья, клинки, броня. Цены растут с глубиной
- **Чат партии не тратит ход** — «кричу: прикрой меня» работает в любой момент, даже не в свою очередь
- **Кооп 2–4 через P2P** — без сервера: хост создаёт комнату, друзья входят по 4-значному коду. Пошаговая партия, персональный туман войны, общий ИИ-мастер издевается над всеми
- **Обрыв связи не убивает героя** — 3 минуты на возврат по тому же коду и имени, свой слот и свой инвентарь на месте
- **Permadeath + зал славы** с эпитафиями («съеден кракеном»)
- **4 темы терминала** (янтарь / фосфор / лёд / кровь) + секретная тема за 10 смертей
- **CRT-атмосфера**: включение с полосой развёртки, скан-линии, зерно, опциональное мерцание
- **ASCII-аватары из ника** — детерминированный портрет, одинаковый у всех игроков
- **Динамика**: тряска и красная вспышка при уроне, катящийся ASCII-кубик d20, глитч-распад при смерти, кинематографичное вступление
- **Пасхалки**: матричный дождь на заставке, команда «кофе»
- Любой OpenAI-совместимый провайдер (OpenAI, DeepSeek, OpenRouter, Ollama)
- Офлайн-режим с заглушкой ДМа — играется без API-ключа

## Играть онлайн

**https://zxcpap14.github.io/dnd-by-zxcpap14/** — ничего устанавливать не нужно.

Кооп: хост выбирает «Кооп: создать комнату» → получает код → друзья выбирают «Кооп: войти по коду». Ход — по очереди; ИИ и кубики считает хост (принцип «рефери один»).

Соединение P2P через WebRTC с STUN + бесплатным TURN (Open Relay) — пробивает NAT в большинстве домашних сетей. Сигналинг работает по двум каналам сразу:

- **Trystero** — знакомство через публичные Nostr-релеи. Работает **из РФ без VPN**: единого сервера, который можно заблокировать, нет.
- **PeerJS** — классический брокер. Используется как запасной путь и включается автоматически, если релеи недоступны.

Хост поднимает оба канала одновременно, клиент пробует сначала релеи, затем PeerJS — поэтому «молчаливого висяка» не бывает. Если игрок из очень строгой корпоративной сети не подключается — пусть попробует мобильный интернет или другой Wi-Fi.

### Если связь оборвалась

- Клиент видит экран «⚡ СВЯЗЬ ПОТЕРЯНА» и сам переподключается каждые 3 секунды — код и имя уже известны.
- Хост при этом **не убивает героя**: он ждёт 3 минуты, а партия видит его в лобби как офлайн. Вернулся — герой, HP и инвентарь на месте.
- Хост перезагрузил вкладку? На старте появится «ПРОДОЛЖИТЬ» — комната поднимется **с тем же кодом**, и клиенты вернутся сами.
- Если игрок не вернулся за 3 минуты — герой растворяется в темноте с эпитафией «сбежал из подземелья по-английски».

Технические детали надёжности (чтобы «висяков» не было даже в плохих сетях):

- **Heartbeat**: клиент стучится к хосту каждые 8 секунд. Если 24 секунды тишины — WebRTC не заметил обрыва, но игра его замечает и уходит в переподключение.
- **Полумёртвый сокет**: если старый вход молчит больше 20 секунд, вернувшийся по тому же имени забирает свой слот, а не получает «игра уже началась».
- **Герой выбывшего не блокирует партию**: если выбыл тот, чей сейчас ход, очередь сразу переходит живому.
- **Смерть от ДМа тоже передаёт ход** — иначе партия ждала бы мёртвого героя вечно.

### Торговец

После спуска на новый этаж появляется лавочник: 3–4 товара, цены растут с глубиной. В панели «⚖ ТОРГОВЕЦ» есть кнопка «КУПИТЬ», в рюкзаке рядом с предметами — «ПРОДАТЬ» (40% ценности). Покупка **не тратит ход**. Уйти — «ухожу».

## Запуск локально

```bash
npm run build     # собирает dist/index.html (один файл, без зависимостей)
npm run serve     # http://localhost:8080
# либо просто открой dist/index.html в браузере
```

## Разработка

```bash
npm test          # тесты движка (node --test, без зависимостей)
npm run check     # тесты + сборка (то же гоняет CI на каждый пуш)
```

Сборка падает с ошибкой, если в бандле оказались два одинаковых имени (`const sleep` в двух модулях) — иначе страница молча не запускается.

Проверки в браузере (нужен локальный Chrome/Edge и `playwright-core`):

```bash
node ../smoke-save.mjs        # автосейв → перезагрузка → «продолжить»
node ../smoke-shop.mjs        # торговец: витрина, покупка, продажа
node ../e2e-reconnect.mjs     # обрыв связи и возврат клиента (реальные релеи)
node ../e2e-connection.mjs    # матрица: неверный код, тёзки, опоздавший, перезапуск хоста
BLOCK_PEERJS=1 node ../e2e-trystero.mjs   # имитация РФ: только релеи
```

Структура:

```
src/
  engine/   — чистая логика: rng, map, player, combat, parser, merchant, game, save, snapshots
  ai/       — клиент OpenAI-совместимый, промпт ДМа, офлайн-заглушка
  net/      — кооп: протокол, loopback, сессии хост/клиент, транспорты Trystero + PeerJS
  ui/       — терминал, typewriter, WebAudio-звук, склейка
  test/     — node:test
build.mjs   — сборка модулей в dist/index.html + docs/index.html (GitHub Pages)
```

Детальный план мультиплеера с уязвимыми местами: `docs/COOP_PLAN.md`.

## Дизайн-принцип

**«ИИ предлагает — код решает».** ИИ никогда не меняет состояние игры напрямую:
он возвращает JSON с намерениями (урон, лут, квест), а движок валидирует и применяет.
Все броски кубиков — детерминированный seeded RNG в коде. Поэтому permadeath по-настоящему страшен.
